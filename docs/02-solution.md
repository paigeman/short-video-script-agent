# 方案

## 当前实现

`src/main.py` 负责读取 JSON 对象并返回明确的未实现状态。当前没有模型、业务工具或 Agent 循环。

## 计划结构

| 模块       | 计划职责                                   |
| ---------- | ------------------------------------------ |
| CLI        | 输入解析、输出 JSON 和退出码               |
| 模型适配   | 配置模型、提交观察结果、读取结构化动作     |
| Agent 循环 | 执行动作、积累观察、限制步数、维护状态     |
| 素材检索   | 返回素材事实和稳定来源 ID                  |
| 时长检查   | 估算各分镜和总时长，返回超限信息           |
| 规则检查   | 检查事实依据与品牌规则，返回可修改的问题   |
| Trace      | 记录参数、返回摘要、后续动作与简要决策依据 |

模型在循环中选择检索、编写或修改脚本、调用检查工具、请求信息或结束。预设代码负责工具协议、边界和状态约束；后续业务动作需由模型依据实际观察决定。

## 两条计划演示的路径

1. 素材充分，首稿检查通过，模型结束并提交结果。
2. 首稿超时长或违反规则，模型观察检查结果后修改，再检查并结束；无法修正则报告未完成。

另需覆盖资料缺失和工具失败时的行为，不能通过预先写好的 Trace 证明动态决策。

## 待确定的取舍

- 模型服务、SDK 或框架，以及实际使用版本。
- 执行上限、工具超时和失败处理策略。
- 时长估算算法、适用文本范围与误差说明。
- 输出与动作的数据结构，以及事实依据校验边界。

先完成可运行的核心链路，再根据实测结果决定是否增加依赖。若提供离线模式，需与真实模型模式分开标识。

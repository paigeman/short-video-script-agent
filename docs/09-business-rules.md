# 短视频业务规则

## 请求与素材

必填字段为 `topic`、`audience`、`platform`、`duration_seconds`、`style`、`product_id`。字符串先去除首尾空白，空值视为缺失；不会把字符串数字或布尔值自动转换为时长。缺失时返回字段清单，非法类型或额外字段返回输入错误。时长限制为 1–300 整数秒。

素材文件必须标明 `synthetic=true`，来源 ID 唯一。事实 ID 按素材内顺序生成，例如 `M01:F1`。替换素材后应重新运行，事实 ID 本身不代表跨文件版本不变的事实。

`search_materials` 只搜索请求指定的产品。匹配产品 ID、素材 ID、英文词和中文相邻双字，按匹配分数及来源 ID 稳定排序。它支持改写查询，但不是语义向量检索。最多返回 5 条素材，事实原文整体按约 16 KB 预算返回，超限标记 `truncated`，不会截断事实句子或把未返回的事实记为已检索。

无结果不自动编造素材或切换产品。模型可改写查询、调用 `ask_user` 或返回未完成。模型追问的回答会回到当前上下文，但不会自动写入可信素材库；增加事实应先更新合成素材文件，再重新运行。

## 候选脚本与检查记录

草稿包含 `title` 和 1–12 个 `scenes`。每个分镜包含唯一 `id`、`visual`、`narration`、`subtitle`、`hold_seconds`、`fact_ids`。旁白和字幕至少一个含有效文本，支持以下镜头类型：

| visual           | 用途                           |
| ---------------- | ------------------------------ |
| `title_card`     | 标题卡                         |
| `screen_demo`    | 操作界面演示                   |
| `screen_closeup` | 字幕区域特写                   |
| `step_card`      | 步骤提示卡                     |
| `recap_card`     | 已引用事实与获准过渡语的回顾卡 |
| `closing_card`   | 结束卡                         |

画面描述为编辑示意，不虚构未提供的按钮、操作或产品效果。教学与速览的结构由模型依据请求选择，文案仍受同一事实规则约束。

请求可选 `initial_draft`，其结构与上述草稿相同，不能附加自称已通过的字段。它是待修改稿件，不是可信素材或预先通过的交付。提示要求检索后先原样估时与检查，再根据反馈修订；只有实际完成检查的最终版本才可交付。

`estimate_duration` 接收完整草稿，按规范 JSON 内容计算 `draft_id` 并保存估时结果。`check_rules` 接收该标识，检查对应草稿。每个工具还要求简短的 `reason` 说明动作目的，用于运行记录，而非模型内部推理。

最终动作只有两类：

```json
{ "status": "completed", "draft_id": "实际工具返回的64位内容标识" }
```

```json
{ "status": "incomplete", "reason": "cannot_meet_constraints" }
```

后者也可使用 `no_materials`、`tool_failure` 或 `insufficient_information`。前者只有在同一草稿实际通过估时和规则检查后才会交付。示例中的标识说明文字不是合法可执行标识。

程序最终再核对草稿内容、检查记录、产品引用与目标时长，并从记录组装分镜时长和来源，拒绝缺检查、未通过检查、不同版本或修改后的草稿。

## 时长估算

参数来自 `data/brand_rules.json`，当前默认值如下：

- 连续英文字母作为一个单词单位，中文等非 ASCII 字母每字一单位，数字每位一单位。
- 口播速率为每秒 4 单位，常见停顿标点每处增加 0.15 秒。
- 字幕阅读速率为每秒 6 单位。
- 每个分镜取口播估时、字幕阅读估时、模型指定画面停留的最大值。
- 各分镜向上取整到 0.1 秒，再加镜头之间每次 0.4 秒转场。

工具返回各项分解、总时长、超出秒数、通过状态和使用的参数。分镜的 `start_seconds`、`end_seconds` 由累计镜头时长与转场计算，交付时直接使用该检查结果。累计转场向上取整到 0.1 秒，最后一镜结束时间等于总时长。

总时长不得超过请求上限，不会因无法满足而提高用户的时长要求。该计算是确定性估算，不代表真实口播、剪辑或观看效果。

## 事实与品牌规则

| 规则         | 实现                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| R01 来源支持 | 每条引用必须存在、属于请求产品、已经检索，且对应本分镜实际使用的完整事实原文                 |
| R01 文案覆盖 | 标题、旁白、字幕必须由引用事实与 `neutral_copy` 中的获准过渡语组成；未覆盖内容阻止交付       |
| R02 量化依据 | 没有完整原文支持的数值、效率或收益表述不允许通过；不会把 0.8 与 08 视为相同文本              |
| R03 品牌禁用 | 对 `prohibited_phrases` 做规范化匹配，命中即拒绝；当前策略包括保证、百分之百、行业第一等表述 |
| 结构完整     | 标题、分镜文案有效，分镜 ID 唯一，整个脚本至少使用一条有效产品事实                           |

文案比对允许 Unicode 宽度规范化、大小写和空白差异；保留事实内部标点后匹配完整表述，避免改变小数或数值含义。事实与过渡语之间可添加普通标点。过渡语清单由资料维护者审查，模型不能修改它。

这是保守的封闭文案规则，不是通用语义事实核查。它会拒绝不少正确的同义改写，也不能保证组合后的表达质量、主题贴合度、受众适配与风格。不得将规则通过声称为全面的内容审核或真实效果验证。

## 故障、记录与验收

工具故障会进入通用执行器的错误回传。真实模型自行决定是否重试、修改动作或停止；离线替身为验收设置一次恢复或持续失败场景。模拟开关只允许在离线模式使用，输出明确标记 `mode=offline`。

`trace` 保存模型与工具交互，`tool_records` 保存完整业务参数及实际返回，`drafts` 保存各版候选与检查记录，顶层 `script` 只保存通过最终核验的交付版本。运行记录可能含请求与素材文本，真实使用时需要决定哪些内容适合公开。

离线验收覆盖题目必验场景，以及规则修订、持续故障、上限停止和伪造完成结果。最新真实验收包含十一条模型路径与缺字段校验，增加了已有稿件压缩与两种风格检查。具体输入、命令、输出见 [评估](03-evaluation.md)和[审核补强](13-review-strengthening.md)；此前结果另存于[截点后记录](12-post-checkpoint-acceptance.md)。

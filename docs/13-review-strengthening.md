# 审核要点补强

本次为用户要求的进一步补强，发生在 3 小时截点之后。冻结快照、此前的真实验收和失败记录保持不变。

## 已有稿件超时后成功压缩

新增可选输入 `initial_draft`，支持修改已有脚本。它仍需符合草稿结构，并经过素材检索、原稿诊断、模型修订和同一修改稿的复检，不能因来自用户或历史运行而获得可信状态。

本例原稿来自此前真实模型在 30 秒上限下生成的 [14.2 秒脚本](../examples/live/20261029-post-checkpoint/normal.output.json)。现在将上限缩短为 10 秒，通过原样检查得到真实超限结果，再由模型选择如何压缩。它验证的是“已有稿件在新要求下超时后的修订”，不声称模型在相同约束下故意生成了不合规首稿，也没有伪造工具估时。

| 步骤               | 实际结果                                                         |
| ------------------ | ---------------------------------------------------------------- |
| 检索原稿使用的素材 | 返回 M01:F1、M01:F2                                              |
| 原样估时并检查     | 14.2 秒，超过 10 秒；引用规则通过                                |
| 模型调整           | 四镜头改为三镜头，减少停留、删除重复过渡与结束卡，两条事实均保留 |
| 修改稿估时         | 8.3 秒，不超过 10 秒                                             |
| 修改稿规则检查     | 通过，使用新的 draft_id                                          |
| 最终交付           | 8.3 秒脚本，来源与实际检查一致                                   |

[输入及原稿来源](../examples/live/20261029-strengthening/duration-repair.input.json)保存来源路径与文件 SHA-256；[完整输出与 Trace](../examples/live/20261029-strengthening/duration-repair.output.json)保留原稿和修改稿。验收器要求先观察原稿真实超限，再观察不同稿件通过；首稿直接合规不会被记作压缩成功。

最终时间轴由估时器计算，镜头间包含 0.4 秒转场：

| 时间       | 镜头         | 旁白                 | 来源       |
| ---------- | ------------ | -------------------- | ---------- |
| 0.0–2.0 秒 | 标题卡       | 功能小演示           | 中性过渡语 |
| 2.4–4.9 秒 | 界面演示     | 支持生成字幕草稿     | M01:F1     |
| 5.3–8.3 秒 | 字幕区域特写 | 支持手动修改字幕文本 | M01:F2     |

## 文案组织与镜头表达

镜头类型从三种扩展为六种，新增 `screen_closeup`、`step_card`、`recap_card`。模型可按受众、平台与风格选择结构；新增获准词仅为步骤和回顾等中性过渡语，没有放宽产品事实原文或数字依据要求。镜头描述为剪辑示意，不杜撰具体按钮、操作步骤或产品效果。

每个交付分镜新增 `start_seconds`、`end_seconds`。它们与估时工具的结果一致，累计转场采用同一向上取整规则，最后一个镜头的结束时间与总时长一致。

| 风格         | 实际结果                                                      | 证据                                                                                                                                                   |
| ------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 新手教学     | 17.8 秒，步骤卡、字幕区域特写、字幕回顾；保留教学层次         | [输入](../examples/live/20261029-strengthening/style-tutorial.input.json) / [输出](../examples/live/20261029-strengthening/style-tutorial.output.json) |
| 熟练受众速览 | 15.2 秒、四镜头，两个事实各集中在一个特写镜头，无重复功能讲解 | [输入](../examples/live/20261029-strengthening/style-teaser.input.json) / [输出](../examples/live/20261029-strengthening/style-teaser.output.json)     |

初版速览虽然事实合规，却用了七个镜头、25.9 秒，每条事实重复出现三次。复核后补充了不重复铺陈、不为凑满时长增加镜头的提示，并增加速览专用的镜头数与跨镜头事实去重验收。[初版结果](../examples/live/20261029-strengthening/initial/style-teaser.output.json)和[问题记录](../examples/live/20261029-strengthening/initial/style-teaser.review.json)保留，没有被新结果覆盖。

## 复验与判定更正

完整一轮覆盖十二个场景，其中十一个实际调用模型，缺字段场景在本地结束；合计 50 次模型请求、54 次业务工具执行。原有正常、无素材、工具失败、无法满足时长、无依据主张等场景全部保留。

初始自动判定为 11/12：教学版使用了界面特写，而验收器只认可完整界面镜头。原请求要求展示操作画面，特写也符合该要求；验收器因此改为接受两种界面展示，仍要求步骤卡、回顾和实际界面类镜头。新增回归测试防止把纯文字卡当成操作展示。

修正后离线复核同一批原始输出，十二项均符合预期，没有重新生成或修改模型结果。原始 [manifest](../examples/live/20261029-strengthening/manifest.json)保留最初判定；单独的 [assessment-review](../examples/live/20261029-strengthening/assessment-review.json)记录更正理由、当前验收器摘要及逐项复核。运行时源文件与执行时摘要一致，验收脚本因这项判定更正与原始摘要不同，以复核记录中的 `evaluator_sha256` 为准。

最终 `npm test` 的 145 项离线测试通过，见 [最终测试记录](../examples/strengthening-final-test-results.txt)。此前的 [144 项记录](../examples/strengthening-test-results.txt)也保留。新增测试覆盖旧稿未验证状态、压缩后重新检查、伪造压缩证据、时间轴取整、镜头与引用一致性及风格判定。

## 复现与边界

```shell
uv run --locked --env-file .env python -m src.main --mode live --input examples/revise-existing.input.json
uv run --locked --env-file .env python -m scripts.live_acceptance --output-dir .agent-tmp/review-check --case duration-repair --case style-tutorial --case style-teaser
```

新增能力和结果仍只针对合成资料。风格验收检验明确的结构偏好，不代表独立人工评价的创意质量；文案仍限制为事实原文与过渡语，真实配音和画面制作未验收。模型可能产生不同稿件，验收以实际结果为准。所有运行由 uv 加载本机凭据，未查看、输出或提交密钥。
